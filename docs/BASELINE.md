# 手工核对基准

所有数字都可以只用 `data/orders.json` 和四则运算复算。金额单位：分。
分摊使用"整数最大余额法"，按商品原价（优惠）或商品件数（运费）加权，
余数按商品原始位置序号从前往后 +1。

ORD-1001 增加 1 条优惠（FREESHIP 300）、1 条履约（SF003 运费 300，件数 1），
版本变为 v2。复算：

- 优惠总额 5150 → 5450；分摊优惠 4850 → 5150；净额 37950 → 37650。
- 履约运费 3450 → 3750；分摊运费 3200 → 3500；到手成本 41150 不变
  （净额 −300，运费 +300）。
- ORD-1001 商品分摊：优惠 2300（4000/3000/3000 权重重算），运费 1500
  （件数权重 2:1:3），到手 9200 不变。
- 只有 ORD-1001 的 version 与 plan_hash 变化，其余订单不受影响。

## 8. 结构与缓存

- 每订单计划哈希 = `sha256({order_key, order_version, projection, grain, filter, shape})`；
  更正、升级、数组规模变化都会改变它。
- 数据集摘要 = 所有订单 `(order_key, version, projection, plan_hash)` 的排序哈希。
- 发布缓存 = 写入事务内重算数据集摘要并比较；不等则拒绝，旧条目保留在
  `result_cache`（append-only），`result_head` 只指向最新成功发布。
- 升级（projection+1）不改变任何业务数值，只改变计划哈希与数据集摘要。
